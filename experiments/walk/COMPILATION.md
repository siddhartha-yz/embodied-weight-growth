# 脚踝分工能写进原来的权重网络

首轮的权重 v8 是一层线性映射（最后限幅）。左右髋、膝的时钟项取相反符号，但两个脚踝始终使用同一种反馈：

```text
u_ankle = 0.08 − 0.40·踝角 − 0.012·踝角速度 − 0.25·机身前进速度
```

代码 v8 按 `sin(7t)` 的符号切换双腿角色。支撑脚踝用腿姿态估计脚相对身体的位置，并用前进速度做反馈；摆动脚踝把脚掌放平，不对前进速度做反馈。该代码也有不同的髋、膝和时钟设定，所以不能仅从两版原控制器的对比归因。只去掉代码 v8 的两条摆动脚踝覆盖、保留其余逻辑时，原起姿在 3.04 秒后摔倒；新倾角曾达到行走判据，随后在 3.58 秒摔倒。完整代码在两种起姿都走满 5 秒。

## 在原运行时里实测

Walker2d、seed 271、初始条件、25 个输入、20 ms 控制步和停止条件均沿用首轮。每次从复位状态开始冻结运行 250 步（摔倒时提前停止）；不调用 Astra。

| 模块 | 原起姿：0.02 rad | 新倾角：0.08 rad |
| --- | --- | --- |
| Astra 原权重 v8 | 1.44 m / 1 步，1.64 秒摔倒 | 1.27 m / 1 步，1.42 秒摔倒 |
| 代码 v8 | 2.71 m / 11 步，5 秒未倒 | 2.87 m / 11 步，5 秒未倒 |
| 编译权重 | 2.79 m / 11 步，5 秒未倒 | 2.58 m / 9 步，5 秒未倒 |
| 蒸馏权重 | 2.67 m / 11 步，5 秒未倒 | 0.76 m / 4 步，2.06 秒摔倒 |

编译器用 tanh 门在两个相位选择不同的反馈公式，并近似代码中的时钟、启动坡道和脚部几何。支撑脚几何的局部系数只用原起姿轨迹拟合；相位切换按原实验 20 ms 采样格构造，适用范围是本次 5 秒评估。部署只提交原接口允许的 `25→24→24→6` 稀疏数字权重，运行时没有分支代码、额外特征或教师控制器。把同一批教师状态送给两者时，六路归一化力矩的 RMSE 分别是 0.00338（原起姿轨迹）和 0.00346（新倾角轨迹）。固定其他输入、单独扰动脚踝角和前进速度时，编译网络也复现了代码的支撑／摆动反馈差异。

蒸馏是独立对照：用原起姿的 250 个教师状态及附近扰动样本做监督拟合，选第一个在原起姿走满 5 秒的版本，再冻结测试新倾角。它复现了原起姿的步态，但没有复现新倾角的稳定性。

**结论：** 同一个允许的两隐藏层网络能装下这套分工；原权重 v8 选用的线性控制器没有相位相关的脚踝反馈。本轮区分了表达能力与一次直接生成的结果；编译和蒸馏都使用了现成代码作为教师。

## 复现

```bash
run=results/271-walk-v1
mkdir -p runs
python experiments/walk/compile_v8_analytic.py \
  "$run/code/frozen/train/v08.json" "runs/compiled-v8.json"
python experiments/walk/compare_v8.py "$run" --out "runs/compile-v8-replay" \
  --ablate-code --weights "compiled=$run/compile-v8/reproduced.json"
```

用课题组服务器时，给第二条加上 `--ssh-host`、`--python`、`--remote-server` 和所需的 `--remote-pythonpath`，同 [行走试跑](README.md)。蒸馏脚本是 `distill_v8.py`，拟合使用 PyTorch；部署和重放只需原来的 MuJoCo 运行时。
