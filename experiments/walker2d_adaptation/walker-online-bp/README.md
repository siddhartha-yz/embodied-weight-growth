# Walker2d：在线 BP 对照

**两组都没有稳定适应新地面。40 次试跑后，Astra 组在新地面通过 5/12，直接 BP 通过 3/12；换回旧地面分别通过 10/12 和 0/12。Astra 五次都选了只更新输出层，因此这次的结果可由固定的输出层更新复现，无需在线问 Astra。**

## 公平对照

- 从之前 WSP/BP 使用的原始蒸馏检查点开始。在课题组服务器用同一 MuJoCo 模型，原地面保留默认，新地面让双脚有效滑动摩擦系数都为 0.46；电机、观测和时间步均未变。
- 两组每批 8 次，5 批共 40 次，每次最多 250 步（5 秒），用相同的训练起姿种子和探索噪声序列。摔倒提前停止，所以实际物理步数分别为 7,152 和 7,732。两组共用奖励、PPO 更新和旧地面动作保持项，没有 v8 教师或正确动作标签。保持项的标签是原策略在三次共同旧地面试跑上的自身输出。
- 直接 BP 每批更新全网。Astra 通过 Codex SDK 看到每批真实试跑反馈后只选更新或跳过、以及参数块；不参与发动作、不填权重、不另写控制器。两组均做了 60 次梯度更新；前者每批更新 1,206 个已有系数，后者每批 150 个输出层系数。
- 两组全部锁定后，用相同的 12 个未见起姿无噪声冻结复测每个检查点。单局判据沿用走满 5 秒不摔、至少 1 米、至少 4 次交替落脚；适应速度判据是连续两个检查点至少 8/12 通过。最后换回原地面，不更新，复测同批起姿。
